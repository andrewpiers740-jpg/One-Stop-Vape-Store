- Brotli compression on every page (home HTML 1,067 KB uncompressed, 48 KB sent). Warm first-byte time about 0.45 s.
- Security headers present: X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, HSTS. CSP is in report-only mode.

- One H1 per page, unique titles and meta descriptions, canonical tags, no broken links on the pages checked, no mobile overflow.

### 3.2 Open: not changed, with how to fix

1. **Image delivery (largest remaining speed lever).** PageSpeed estimates 443 to 913 KiB of savings: product photos are served at full size and scaled down by CSS. Cause: `images.unoptimized` is on by design (CLAUDE.md), so no responsive sizes are generated. Fix: add a thumbnail step to the image scripts (for example 400 px wide WebP for product cards) and point cards at the thumbnail, or switch product cards to the Vercel image optimizer. Check the Vercel image quota before switching.
2. **Category page LCP 4.2 s on Google's throttled mobile test.** Partly fixed by items 7 and 8 above. If it is still over 2.5 s after the deploy, shrink the banner on mobile (the 1920x480 file is shown 160 px tall) by adding a 960 px mobile version.
3. **Page size and DOM.** Home is 1,067 KB of HTML (about half is server-rendered React data) and 3,548 DOM elements; category pages about 3,100 elements. It does not hurt the Google score today, but it drives hydration cost on slow phones. Fix: render fewer product cards on the home page and category page 1 (for example 24 instead of all), and load the rest with the existing pagination.
4. **Response time and request count (Rank Math).** 0.80 s response from its test server (target 0.8 s or less) and 36 requests per page. Most are images. Lazy-loading below-the-fold images and the thumbnail step above reduce both.
5. **Render-blocking CSS and legacy JavaScript.** PageSpeed estimates 40 to 130 ms and 12 KiB of savings. Low priority. Fix: set Next's `experimental.optimizeCss`, and raise the browserslist target to drop legacy polyfills.
6. **Content-Signal flagged by Lighthouse.** Lighthouse's SEO audit reports `Content-Signal: ...` in robots.txt as an "unknown directive" (92 instead of 100 locally; Google's own run scored SEO 100). It is a newer standard that agent scanners reward. Keep it.
7. **Colour-contrast warnings in desktop Lighthouse.** These come from the fading review carousel being captured mid-animation; the text itself meets contrast. No change.
8. **Agent readiness items that cannot be fixed in code.** DNS-AID records (needs special DNS records added at your domain registrar; not something the website code can do), Web Bot Auth signing, and the optional commerce protocols. Score impact is small.
9. **Optional rich-result fields.** `aggregateRating` and `review` are missing on products. Left out on purpose: no invented reviews. Add them only when real, attributable review data exists.
10. **CSP is report-only.** Safe to leave; switching to enforced needs testing against the chat widget and payment pages first.
